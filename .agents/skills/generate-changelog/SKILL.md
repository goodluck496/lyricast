# Скилл: Генерация ченжлога релиза LyriCast

Этот скилл предназначен для автоматического сбора, категоризации и оформления Release Notes (списка изменений) из git-истории проекта LyriCast.

## Как запустить

### 1. В составе команды релиза
Скрипт автоматически вызывается в процессе выполнения команды релиза:
```bash
npm run release
```
После ввода типа релиза (`patch`, `minor`, `major`) скрипт:
1. Повышает версию в `package.json`.
2. Автоматически собирает коммиты и описания изменений с момента предыдущего релиза.
3. Выводит красиво оформленный ченжлог в консоль.
4. Сохраняет итоговый Markdown в файл `RELEASE_NOTES.md`.
5. **Копирует текст в буфер обмена операционной системы** (Windows `clip`, macOS `pbcopy`, Linux `xclip`), откуда его сразу можно вставить в GitHub Release, Telegram или карточку задачи.

### 2. Отдельная команда в любое время
Сформировать актуальный ченжлог для текущего состояния проекта можно командой:
```bash
npm run changelog
```
или с явным указанием диапазона коммитов:
```bash
node tools/generate-changelog.mjs <from-commit-or-tag> [to-commit-or-tag]
```
Примеры:
```bash
# Ченжлог от тега v2.7.1 до текущего HEAD:
node tools/generate-changelog.mjs v2.7.1 HEAD

# Ченжлог от конкретного хэша коммита:
node tools/generate-changelog.mjs fd270fa
```

## Категоризация изменений

Скрипт автоматически анализирует тему и тело каждого коммита, распределяя их по ключевым секциям:
- **📖 Переводы Библии и справочники**: изменения по Библиям, SQLite MyBible, справочникам.
- **🔄 Автообновление (Auto-updater)**: механизмы автообновления, фоновые загрузки, оверлеи.
- **🔐 Авторизация и доступ (Google OAuth 2.0)**: OAuth, токены, права владения (`ownerEmail`).
- **🔍 Поиск и навигация**: поиск стихов, плавающие панели, навигация.
- **🚀 Новые возможности**: фичи (`feat:`), пользовательские доработки.
- **🛠 Исправления и оптимизация**: багфиксы (`fix:`), оптимизация SQL/производительности.
- **📝 Прочие изменения**: технические правки, зависимости, настройки.

Если у коммита есть многострочное описание (body с дефисами или буллетами), они автоматически включаются как вложенные подпункты.
